该微信小程序项目采用简洁的 TypeScript + JSON 配置文件组合来管理运行时配置，没有引入外部配置框架或环境变量注入机制。

**配置分层与加载方式：**
- **应用级常量配置**：`miniprogram/config.ts` 集中导出 `BASE_URL`（后端 API 基地址）和 `DEFAULT_STORE_ID`（默认店铺ID），通过 ES Module 暴露供各模块 import 使用。请求层 `utils/request.ts` 直接引用此文件拼接完整 URL。
- **小程序全局配置**：`miniprogram/app.json` 声明页面路由、窗口样式、自定义 tabBar、Skyline 渲染选项、组件框架等小程序平台级配置。
- **开发者工具配置**：`project.config.json` 定义编译插件（TypeScript、Sass）、模拟器类型、基础库版本、打包忽略规则等；`project.private.config.json` 存放本地私有设置（如 AppID、开发开关），不提交到版本控制。
- **运行时状态**：`app.ts` 通过 `App()` 初始化 `globalData` 存储用户信息和店铺 ID，并在 `onLaunch` 中根据登录态恢复或跳转登录页。

**设计特点：**
- 无 `.env` 文件或环境变量读取逻辑，所有环境差异通过修改 `config.ts` 中的 `BASE_URL` 切换。
- 无 feature flag 或动态配置中心集成，配置均为静态常量。
- 请求层统一处理 401 未授权场景，自动清除 token 并跳转登录页，具备简单的错误提示机制。
- 配置与业务代码紧耦合，未抽象出独立的配置管理服务。

**开发者约定：**
- 修改后端 API 地址只需编辑 `miniprogram/config.ts` 中的 `BASE_URL`。
- 新增页面需在 `app.json` 的 `pages` 数组中注册路径。
- 开发环境与生产环境的切换需手动修改 `config.ts`，或通过构建脚本替换变量（当前未实现）。
