该微信小程序项目采用分层错误处理策略，核心围绕 `utils/request.ts` 中的 HTTP 请求封装实现统一错误处理，页面层通过 try/catch 捕获并展示用户友好的错误信息。

**HTTP 层统一错误处理**
- `request.ts` 封装 `wx.request`，定义统一的 `ApiResponse<T>` 结构（code、msg、data）
- 401 未授权：自动清除 token、提示「登录已过期」并跳转到登录页，同时 reject Error('未授权')
- 业务错误（code !== 200）：根据 `silent` 选项决定是否 showToast，reject Error(data.msg)
- 网络异常：fail 回调中统一提示「网络异常，请稍后重试」，reject Error(err.errMsg)
- 提供 `get/post/put/del` 便捷方法，支持 `silent` 选项静默处理特定场景的错误

**认证与状态管理**
- `utils/auth.ts` 提供 token 和用户信息的存取、登录状态检查、角色判断等工具函数
- `checkLogin()` 在未登录时自动跳转登录页，避免重复跳转
- `app.ts` 启动时恢复全局登录态，未登录直接重定向到登录页

**页面层错误处理模式**
- 登录页 (`pages/login/login.ts`)：使用 `status: 'loading' | 'error'` 状态机，错误时设置 `errorMsg` 供 WXML 展示
- 其他页面普遍采用 try/catch 包裹异步操作，catch 中记录 `console.error` 并更新 UI 状态
- 部分页面存在空 catch 块（`catch (e) { /* ignore */ }`），用于忽略非关键操作的失败

**错误传播链**
后端响应 → request 封装层解析 code/msg → Promise reject → 页面层 catch 捕获 → 用户可见的 toast 或页面状态更新

**约定与限制**
- 所有网络请求必须通过 `utils/request` 发起，禁止直接使用 `wx.request`
- 业务错误码由后端统一返回，前端仅做透传和展示
- 无自定义错误类型类，统一使用原生 `Error` 对象
- 无全局错误处理器或中间件机制
