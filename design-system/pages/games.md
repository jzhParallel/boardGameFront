# 桌游页面规范

适用页面：用户端桌游页  
对应代码：

- [games.wxml](D:\code-ai\boardGameFront\miniprogram\pages\user\games\games.wxml)
- [games.ts](D:\code-ai\boardGameFront\miniprogram\pages\user\games\games.ts)
- [games.scss](D:\code-ai\boardGameFront\miniprogram\pages\user\games\games.scss)
- [game-card.wxml](D:\code-ai\boardGameFront\miniprogram\components\game-card\game-card.wxml)
- [game-card.ts](D:\code-ai\boardGameFront\miniprogram\components\game-card\game-card.ts)
- [game-card.scss](D:\code-ai\boardGameFront\miniprogram\components\game-card\game-card.scss)

本规范只基于当前已存在功能编写，不新增、不删减功能。

当前桌游页现有功能只有：

1. 搜索桌游名称
2. 分类筛选
3. 桌游列表浏览
4. 进入桌游详情
5. 通过“怎么玩”进入 AI 助手
6. 分页加载、下拉刷新、空状态

## 1. 页面目标

桌游页的目标不是做成内容社区，也不是做成商城，而是帮助用户更快找到想看的桌游并进入下一步。

页面需要完成的事情：

1. 让用户快速定位某个桌游
2. 让用户快速按类型缩小范围
3. 让用户扫一眼就理解每个桌游的基础信息
4. 让用户在“看详情”和“问 AI”之间顺滑选择

## 2. 页面定位

这是一个“检索 + 浏览列表页”，不是“内容运营页”。

因此页面重心应当是：

- 搜索与筛选清楚
- 列表扫读效率高
- 单张卡片信息简洁
- 功能动作明确

不应该做成：

- 推荐内容流
- 营销会场
- 评分榜单页
- 富信息百科页

## 3. 页面结构

当前结构如下：

1. 搜索栏
2. 分类横向筛选
3. 桌游网格列表
4. 空状态 / 加载状态 / 到底提示

规范要求：

- 保持这个结构，不新增排序、收藏、推荐、排行榜等功能区
- 不增加运营 banner
- 不把页面改成瀑布流内容页

## 4. 信息优先级

桌游页信息优先级固定如下：

1. 搜索
2. 分类筛选
3. 桌游名称
4. 人数 / 时长 / 难度
5. 分类标签
6. “怎么玩”动作

规则：

- 搜索和筛选决定列表效率，应高于卡片装饰
- 桌游名称是卡片第一识别信息
- 元信息用于快速判断，不应被装饰淹没
- “怎么玩”是辅助动作，不应比整个卡片更抢眼

## 5. 搜索区规范

### 5.1 区块角色

搜索栏是桌游页第一功能入口。

它负责：

- 快速定位具体桌游
- 缩短浏览成本

它不负责：

- 表达品牌气质
- 做视觉主角

### 5.2 视觉规则

- 搜索栏应稳定、干净、明显可输入
- 输入框是功能容器，不做夸张造型
- 搜索图标只做识别，不做情绪图形

### 5.3 文案规则

当前 placeholder 为“搜索桌游名称...”，方向正确。

规范要求：

- 保持直接表达
- 不要改成营销式文案
- 不要加入多余副标题

### 5.4 交互规则

- 输入时页面重点转向搜索结果
- `confirm-type="search"` 的动作感要清晰
- 输入框聚焦态与默认态要有轻微区分
- 搜索不应显得“像表单”，而应像轻检索

## 6. 分类筛选区规范

### 6.1 区块角色

分类区负责缩小浏览范围，是桌游页第二功能入口。

当前分类包括：

- 全部
- 策略
- 派对
- 推理
- 合作
- 卡牌
- 桌游

这些功能边界保持不变。

### 6.2 视觉规则

- 分类是筛选器，不是导航栏
- 横向滚动保留
- 默认态轻、选中态强

### 6.3 分类项规则

- 选中态必须明确
- 未选态保持低干扰
- 所有分类项高度和节奏一致
- 不要让分类项像很多独立按钮在争抢注意力

### 6.4 交互规则

- 切换分类后列表应快速重置并刷新
- 当前激活分类要始终可辨识
- 点按反馈可以轻量压暗或轻微透明变化

## 7. 列表区规范

### 7.1 区块角色

桌游列表区是页面主体。

当前使用双列网格，这个结构可以保留。

它适合当前功能，因为：

- 桌游封面有识别价值
- 用户常常需要并排比较
- 卡片信息相对轻量

### 7.2 网格规则

- 双列结构保留
- 卡片宽度、节奏和留白统一
- 列间距与行间距一致，不要忽大忽小
- 页面边距稳定，不让列表贴边

### 7.3 列表浏览节奏

用户扫列表时的阅读顺序应当是：

1. 封面 / 分类标签
2. 名称
3. 人数 + 时长
4. 难度
5. “怎么玩”

这意味着：

- 名称必须最强
- 元信息要紧凑而不拥挤
- 难度是补充维度，不应变成主卖点

## 8. 单个桌游卡片规范

### 8.1 卡片角色

单张卡片是“快速判断 + 二次进入”的入口。

它不应该承载太多信息。

当前已有内容：

- 封面
- 分类标签
- 名称
- 人数范围
- 时长
- 难度星级
- “怎么玩”

这些内容全部保留，不新增描述、评分、价格、评论等字段。

### 8.2 封面规则

- 封面是识别辅助，不是唯一主角
- 封面比例统一
- 空封面占位要干净
- 占位风格不能比真实图片更抢眼

### 8.3 分类标签规则

- 标签只用于快速识别桌游类型
- 标签应小而清晰
- 不要让标签像徽章集合
- 一张卡只保留一个主分类标签

### 8.4 名称规则

- 名称是卡片第一层级
- 单行截断保留
- 不允许被图标和按钮抢层级
- 过长时优先保证卡片节奏，不拉高卡片高度

### 8.5 元信息规则

当前元信息包括：

- 人数范围
- 时长

规范要求：

- 两项并排展示即可
- 视觉弱于名称，强于辅助按钮
- 分隔符只做结构辅助，不要过重

### 8.6 难度规则

当前用星级表达难度。

规范要求：

- 难度是辅助信息，不是推荐排序
- 视觉强度低于名称和元信息
- 已填充和未填充星级区分明确
- 不要让星级像评分系统

也就是说，这里表达的是“上手难度”，不是“用户评分”。

### 8.7 “怎么玩”按钮规则

“怎么玩”是当前桌游页的重要辅助动作，但它属于次动作。

规则：

- 它不能压过整张卡的点击动作
- 它应该看起来可点，但不应像主按钮
- 它更像轻标签按钮或次级动作胶囊
- 它和卡片主体之间要有明显层级区分

## 9. 页面视觉主次

桌游页的视觉层级应固定为：

### 第一层

- 搜索栏
- 列表中的桌游名称

### 第二层

- 分类筛选
- 封面
- 人数 / 时长

### 第三层

- 难度星级
- 分类标签
- “怎么玩”

禁止：

- 所有卡片都靠强阴影和大色块抢眼
- 搜索栏像 banner 一样过重
- “怎么玩”按钮比卡片主体更显眼

## 10. 配色规范

桌游页沿用当前前端色彩体系：

- 主色：`#2D5A45`
- 辅助色：`#A0714F`
- 强调色：`#E8A838`
- 背景：`#FAF6F0`
- 卡片底：`#FFFFFF`

使用规则：

- 主色优先用于当前激活分类和可交互强调
- 卡片底色保持白色，保证列表干净
- 难度星级可以使用强调色，但只限局部
- 不增加新的彩色状态体系

注意：

- 页面不能因为有很多封面就再叠加很多彩色 UI
- UI 应让内容自己丰富，而不是让容器过度出声

## 11. 字体与文案规范

### 字体层级

- 页面功能区文字：14-16，500/600
- 桌游名称：16-18，600
- 元信息：12-14，400
- 难度与辅助动作：12-14，400/500

### 文案规则

- 所有文案以功能表达为主
- 不加入营销式修饰
- 不写“爆款”“热门”“必玩”这类未在当前功能中定义的标签

## 12. 交互逻辑规范

### 12.1 搜索逻辑

- 输入后确认搜索，结果刷新
- 搜索状态应重置分页
- 搜索词存在时页面应体现“当前结果已被筛选”

### 12.2 分类逻辑

- 分类切换后立即触发列表刷新
- 当前分类始终保持高可识别度
- 分类和搜索可叠加，不应造成页面表达混乱

### 12.3 卡片点击逻辑

当前整张卡片点击进入详情，这个逻辑正确，应保留。

规范要求：

- 卡片整体是主点击区域
- “怎么玩”是局部次动作
- 两种动作必须清楚区分，避免误触

### 12.4 AI 助手跳转逻辑

当前“怎么玩”会跳转到 AI 助手，并传递问题。

这个行为应在视觉上体现为：

- 这是一个帮助入口
- 不是商品购买按钮
- 它属于辅助支持，不是主流程终点

## 13. 加载、空状态与到底提示规范

### 13.1 加载状态

- 加载提示应轻，不打断浏览
- 不需要夸张 loading 动画
- 首次加载和分页加载的语气应一致

### 13.2 空状态

当前空状态为“暂无桌游，敬请期待”，功能上可用。

规范要求：

- 空状态简洁
- 不要把空状态做成大插画中心页
- 空状态依然应保留搜索和筛选上下文

### 13.3 到底提示

- “已经到底啦”属于结束反馈
- 语气轻松即可
- 不应抢夺列表内容注意力

## 14. 动效规范

桌游页动效应保持轻量。

允许：

- 分类点击轻反馈
- 卡片点按轻微缩放或压暗
- 搜索聚焦状态轻变化

不允许：

- 卡片悬浮感过重
- 列表项逐个大幅飞入
- 过度阴影动画
- 搜索栏和分类条复杂联动

原则：

- 动效服务浏览和点击确认
- 不服务装饰热闹

## 15. 页面最需要避免的问题

### 结构上

- 私自增加排序、推荐流、排行榜等新功能区
- 为了显得丰富而让桌游页变成内容运营页

### 视觉上

- 卡片太厚重，导致两列列表非常拥挤
- 分类筛选和搜索都太抢眼
- 封面、标签、按钮全部同时高饱和

### 交互上

- 卡片主点击和“怎么玩”动作打架
- 搜索与分类组合后状态不清
- 分页加载感过重，打断浏览节奏

## 16. 验收清单

- 用户进入页面后能立刻看到搜索与分类
- 分类筛选激活态明确
- 卡片中名称最醒目
- 人数与时长信息可快速扫读
- 难度被理解为“上手难度”，不是用户评分
- “怎么玩”是明确的次动作
- 页面不新增任何现有代码中没有的功能区
- 页面更像高效浏览页，而不是运营内容流

## 17. 一句话结论

当前桌游页应该被打磨成“好搜索、好筛选、好扫读的桌游浏览页”，而不是“功能不多就用装饰把页面堆满的内容页”。
